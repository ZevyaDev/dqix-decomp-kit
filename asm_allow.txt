# Addresses that may be landed as hand-written assembly. Nothing else may be.
#
# The project goal is very little asm in the final product, so place() refuses hand-asm by policy.
# That left the DS secure area (0x02000000-0x02000800) with no landing path at all: its stubs are
# BIOS syscalls, a `swi` has no C form, and every DS decomp writes them as assembly. They were
# refused by place() every wave and held back from the batch build for cumulative link drift, so
# none of them had ever landed -- and the coverage number quietly understated the decomp by 11
# functions as a result.
#
# This is an ADDRESS list, not a rule, on purpose: an "asm is fine below 0x02000800" rule would
# open the door to anything that happens to live there. To add a line, the function must have no
# C form that reaches the ROM bytes, and the reason must say why.
#
# Being on this list is permission, not a guarantee of landing. Nine of the stubs below start at
# 2 mod 4, and dsd's lcf concatenates 4-aligned objects, so they cannot be delinked one per file at
# all -- measured +4 downstream drift on an isolated build of 02000216. ov_recover keeps those out
# of waves; they land only if the delink is reshaped to start 4-aligned. See align2_main.txt.
#
# Format: <8-hex addr>  <symbol>  <reason>
